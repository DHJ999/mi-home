# 米家看家

**在自己电脑上登录小米账号，远程观看家里米家摄像头的实时画面与存储卡回放**
不要求与摄像头在同一局域网 · 画面只经过这台电脑

## 这是什么

米家官方没有 PC 端的观看入口，只有手机 App。这个项目在你自己电脑上跑一个小服务，把画面搬到浏览器里：

- **登录**：调起本机 Edge（找不到时用 Chrome）打开小米官方登录页，账号密码、短信、异地验证全部在小米自己的页面完成，密码不经过本程序
- **取流**：拿到云端凭证后，通过小米云的加密 P2P 通道把画面取回本机，不依赖局域网、不需要公网 IP、不用端口映射
- **播放**：ffmpeg 把摄像头原始编码转成 H.264/Opus，浏览器用 WebRTC 低延迟播放，有声音、可全屏
- **回放**：直接读取摄像头存储卡里的录像，按天在时间轴上定位；取流同样走云端 P2P，画面仍只在本机转码

人在外面、公司、老家，只要能上网就能看，通常比官方 App 晚几秒。

## 实测机型

| 设备 | 内部型号 | 画面 | 结果 |
|---|---|---|---|
| 小米智能摄像机 标准版 2K | `isa.camera.hlc7` | 2304×1296 | 直播正常（含声音）、回放正常 |
| 小米室外摄像机 CW500 双摄版 | `isa.camera.hlmax` | 2560×1440 ×2（2.5K） | 双镜头直播正常（含声音）、云台与镜头 1 回放正常 |

两台都按各自最高画质取流：标准版 2K 是机型上限，CW500 的 2.5K 需要单独指定画质档位（程序已内置）。

## 工作原理

```text
浏览器 :1990 ──① 站内登录──▶ Node 服务
                               │ ② 账号 / 设备列表 / 云端凭证（miot API）
                               ▼
                          小米云
                               │ ③ 凭证写入本机配置
                               ▼
go2rtc-cs2.exe :1984 ──④ 打洞(UDP)──▶ 云端 P2P 中继 ──▶ 家里的摄像头
      │ ⑤ 转码为 H.264 / Opus
      ▼
浏览器 <video-rtc> ◀──⑥ WebRTC / MSE（ws://127.0.0.1:1984）
```

- ① 登录在**小米官方页面**完成，本程序只接收结果，不接触密码
- ④ 取流走小米自己的加密通道，与米家 App 是同一套链路
- ⑥ 浏览器与流媒体服务都在本机回环地址，画面不出这台电脑

## 功能

| | |
|---|---|
| 跨网络观看 | 不要求与摄像头同局域网，也不需要公网 IP / DDNS / 端口映射 |
| 官方页面登录 | 密码、短信、异地验证都在 `account.xiaomi.com`，不再反复要求重新登录 |
| 低延迟播放 | WebRTC 传输，几秒延迟，支持声音与全屏 |
| 双镜头直播 | CW500 双摄版两路画面分别连接、分别重试，单路故障不影响另一路 |
| 画质切换 | 自动 / 360p / 2.5K（2K 机型显示 2K），**运行中直接切换，画面不断流** |
| 云台控制 | CW500 支持上 / 下 / 左 / 右转动，**按住持续转、松手即停**，只控制镜头 1 |
| 断线自愈 | 播放中断自动重连；流媒体服务异常退出后点「重新连接」即可拉回 |
| 存储卡回放 | 按天查看 24 小时录像分布，1 小时 / 6 小时 / 全天时间轴；拖动只预览、松手才定位，连续时段自动接续，无录像时段明确标出 |
| 多设备 | 卡片式设备列表，换摄像头只换流，不用重启程序 |
| 凭证本地 | 登录态与会话只存在本机，退出登录立即删除 |

## 快速开始

### 1. 准备环境

| 依赖 | 要求 |
|---|---|
| 系统 | Windows 10 / 11，需已安装 Microsoft Edge（或 Chrome） |
| Node.js | 18 或更高 |
| ffmpeg | 默认读取 `D:\ffmpeg\bin\ffmpeg.exe`，路径不同就改 `app/go2rtc.mjs` 顶部的 `FFMPEG` |

### 2. 下载运行包

摄像头取流靠一个独立程序，不放在仓库里，请到 [Releases][releases] 下载 `go2rtc-cs2.exe`，放进仓库根的 `go2rtc/` 目录。

程序默认从 `E:\Code\mi-home\go2rtc` 读取运行包；仓库不在这个位置时，先改 `app/go2rtc.mjs` 顶部的 `DIR`。

### 3. 启动

```bash
cd app
npm install
```

然后双击 `app/启动.cmd`，或执行 `node server.mjs`，浏览器会自动打开 <http://127.0.0.1:1990>。

## 使用

### 启动

双击 `app/启动.cmd` 会打开一个黑色窗口，**它就是程序本体，看视频时不要关**，最小化即可。重复双击不会冲突：程序发现已经在跑，就只帮你把页面打开。

### 登录

点「打开小米官方登录窗口」，弹出的是小米自己的页面（地址栏为 `account.xiaomi.com`）。账号密码、短信、异地验证都在那里完成，密码不经过本程序。登录成功后窗口自动关闭，页面直接进设备列表，不用刷新、不用重输。

登录态存在 `app/session.json`，下次打开直接进列表。换账号或不再用这台电脑，点右上角「退出登录」，保存的凭证会被删除。

### 观看

- 在设备卡片上点「观看」。首次建立通道约 5～20 秒（要等摄像头被唤醒并完成打洞），之后是连续画面
- 右上角显示 `1/1 路直播中` 或 `2/2 路直播中`；单路状态在画面标题右侧，失败时点该路的「重试此镜头」
- 双摄机型两路画面各自连接，一路慢或失败不影响另一路
- 默认静音播放（浏览器策略），**点一下画面即可取消静音**；画面下方有全屏按钮
- 在米家里新增或改名摄像头后，点「刷新设备」同步列表

### 画质

- 播放时顶栏右侧可切「自动 / 360p / 2.5K」，第三档按机型显示：标准版 2K 是「2K」，CW500 是「2.5K」
- 切换在会话内完成，**画面不断流**，新档位从摄像头的下一个关键帧生效，通常一两秒
- 「自动」交给摄像头自己判断。实测两台在这种模式下都给到机身上限分辨率
- 360p 只有 640×360，带宽约高画质的十分之一；顺带一提，用 360p 建链只要 2 秒多，高清要 4～8 秒
- 双摄机型：切换只作用于镜头 1，镜头 2 的档位在下次连接（点「重试此镜头」或重新进入）时跟着变

### 回放

- 点「回放」进入存储卡回放，默认停在上次看过的日期和位置；首次读取录像列表通常需要几秒
- 上方 24 小时概览里橙色是有录像的时段，点任意位置可以直接跳过去；灰色空档表示没有录到
- 「1 小时 / 6 小时 / 全天」切换时间轴缩放；拖动只预览时间，松手才建立播放流（约 2～4 秒）
- 支持暂停、前进 / 后退 30 秒、静音与全屏；播放到当前取流窗口末尾会自动接续下一段
- 两段录像之间空档超过约 30 秒时不会自动跨过，会显示「本段录像已结束」，点「继续」跳到下一段
- 双摄机型目前只接通镜头 1 的回放，界面会标注镜头 2 暂不可回放；镜头 2 的实时画面不受影响
- 点「返回实时」回到直播。回放与直播不能同时占用同一台摄像头，程序会自动断开旧流并重建

### 云台

- 只有 CW500 双摄版显示云台面板；控制镜头 1，镜头 2 保持固定
- 镜头 1 处于「直播中」后，**按住**面板上的方向按钮，或按住键盘 ↑ ↓ ← → ，云台会持续转动，**松手即停**
- 补发节奏约每 250 毫秒一条，按住 1 秒大约转 3～4 步；画面比指令晚一两秒，看着画面决定按多久就行
- 最长连续转 12 秒会自动停，防止按键卡住；只想挪一点点就按一下就松手
- 云台指令不排队堆叠：上一条落地才发下一条，网络慢的时候节奏自动变缓，不会出现松手后还在继续转

排错看两处日志：黑色窗口的输出，以及 `go2rtc/go2rtc-app.log`。

## 本机端口

| 端口 | 用途 |
|---|---|
| 1990 | 网页界面与接口 |
| 1984 | 流媒体服务 API（仅监听 127.0.0.1，并做来源白名单校验） |
| 8554 / 8555 | RTSP / WebRTC 转发（go2rtc 监听全部网卡，局域网内可访问） |

## 文件与凭证

```
app/        网页与 Node 服务（server.mjs、go2rtc.mjs、browser-login.mjs、public/）
go2rtc/     运行包与运行时产物：go2rtc-cs2.exe、配置、日志
```

| 文件 | 说明 |
|---|---|
| `app/session.json` | 小米登录态，**已 gitignore** |
| `go2rtc/go2rtc-app.yaml` | 流媒体账号凭证，**已 gitignore**，程序每次启动自动生成 |
| `go2rtc/go2rtc-app.log` | 取流日志，排障用 |

这两个凭证文件拿到就等于拿到你的小米账号，**不要发给任何人，也不要提交进任何仓库**。退出登录会删除 `session.json` 并停掉流媒体服务。

## 常见问题

| 现象 | 处理 |
|---|---|
| 页面打不开 | 确认黑色窗口还在运行，地址是 `127.0.0.1:1990` |
| 一直停在「连接云端通道…」后失败 | 先在米家 App 确认摄像头在线，再点「重新连接」；首次建链要等摄像头唤醒 |
| 没声音 | 浏览器默认静音播放，点一下画面即可 |
| 回放一直「正在读取录像列表」或定位失败 | 确认摄像头在线、存储卡正常；回放读取依赖镜头 1 的实时通道，先返回实时确认能播放再重试 |
| 双摄机型回放里没有镜头 2 | 目前只接通镜头 1 的回放，镜头 2 实时画面不受影响 |
| 云台按住没反应 | 确认镜头 1 为「直播中」；画面比指令晚一两秒，按住 1～2 秒再松手看看 |
| 提示端口被占用 | 任务管理器里结束残留的 `go2rtc-cs2.exe` 后重新启动 |
| 提示没有运行包 | 按「快速开始 · 2」从 Releases 下载后放进 `go2rtc/` |
| 反复要求重新登录 | 小米改过密码会让旧凭证失效，退出登录后重新登录一次即可 |

## 已知边界

- **仅 Windows**：登录依赖本机 Edge（或 Chrome），启动脚本是 `.cmd`
- **双摄机型**：实时画面两路都能看；存储卡回放目前只使用镜头 1，界面上会标注镜头 2 暂不可回放；运行中切画质只对镜头 1 生效
- **回放按窗口取流**：每次最多取约 4 分 15 秒的画面，到末尾自动接续；拖动定位会重建取流，需等 2～4 秒
- **云台没有位置回读**：转动结果只能看画面；画面本身有延迟，按住多久合适得靠目测，转多了反向补回来即可
- 首次建链约 5～20 秒，取决于摄像头唤醒速度
- 海外账号需设置环境变量 `MI_REGION`（默认 `cn`）指向对应分区
- 小米修改登录或接口策略时需要跟着更新，不保证长期可用
